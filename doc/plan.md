# 計畫與設計

## 目標
以最小依賴實作現貨網格交易:先把引擎正確性(資金守恆、單格不重疊)與驗證方法做紮實,再談實盤。

## 範圍
- 已做:
  - 引擎:等差 / 等比網格、手續費、停損(連續 / 跳空)、穿價成交
  - 回測(K 線,含 K 線間跳空)、參數掃描(樣本內 / 外)、滾動視窗驗證
  - 模擬盤:WebSocket 即時價(退回輪詢並定期重試)、狀態持久化(原子寫入、檔案鎖)、斷線警報與自動停機、安全結束(訊號只設旗標)
- 未做:實盤下單(交易所 adapter、對帳、部分成交、交易所端停損)、多交易對、動態調格、內建 Telegram / Email 通知

## 設計取捨
- **引擎與 IO 分離**:`GridEngine.on_price()` 只吃價格,回測、模擬盤、未來實盤共用。
- **空檔設計**:現價所在處不掛單,任何時刻恰有 `grids` 張單,避免買單成交補賣單時覆蓋既有賣單(初版 bug,測試抓出)。
- **固定每格數量**:實作簡單、資金不會透支;代價是等比網格各格投入金額不同。
- **保守的執行模型**:穿價才成交;停損遇跳空以當下價格出場;K 線內部路徑取成交較少的走法;不含滑價與委託簿深度,實際表現通常更差。
- **相對容差**:資金 / 持倉足夠與否用相對容差判斷,金額大或價格極低時才不會因浮點誤差漏單。
- **價格來源標記跳空**:由來源(輪詢、WebSocket 重連)決定哪一筆前有看不到的走勢,而不是用固定秒數猜。
- **零依賴**:WebSocket 客戶端自行以標準庫實作;代價是協定細節要自己維護,以本機假伺服器測試。
- **不內建實盤**:真錢下單需要簽名、重試、對帳、部分成交處理,且目前回測 / 滾動視窗都沒有顯示穩定優勢,未驗證前不放進來。
