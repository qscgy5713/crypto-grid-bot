# crypto-grid-bot

加密貨幣**現貨網格交易**工具:純 Python 標準庫(無第三方依賴),提供網格引擎、回測、參數掃描、滾動視窗驗證與模擬盤。
**目前不支援實盤下單**,也不構成投資建議。

## 技術棧
- Python 3.9+,僅用標準庫(`argparse`、`urllib`、`socket`/`ssl`、`unittest`)
- 行情來源:Binance 公開 REST / WebSocket(免金鑰),或自備 CSV / 合成資料

## 安裝與環境設定
無需安裝依賴:

```bash
cd crypto-grid-bot
python3 -m unittest discover -s tests -t .   # 跑測試,看到 OK 即正常
```

## 快速開始

```bash
# 1. 回測:用 Binance 歷史 K 線看策略表現
python3 -m gridbot backtest --symbol BTCUSDT --limit 1000 --lower 75000 --upper 92000 --grids 20

# 2. 參數掃描:格數 × 區間 × 模式,前 70% 樣本內 / 後 30% 樣本外
python3 -m gridbot sweep

# 3. 滾動視窗驗證:訓練段挑參數 → 套到緊接的測試段(比 sweep 更嚴格)
python3 -m gridbot walkforward

# 4. 模擬盤:即時價格、本地模擬成交、不下真單;區間必須包住現價
python3 -m gridbot paper --symbol BTCUSDT --lower 75000 --upper 92000 --grids 20 --stop-loss 71000
```

各子指令的完整參數也可用 `python3 -m gridbot <子指令> -h` 查詢。

## 參數說明

### 網格參數(`backtest`、`paper` 共用)

| 參數 | 預設 | 說明 |
|---|---|---|
| `--lower` | 必填 | 區間下緣價。價格跌破它,所有買單都已成交,手上全是幣(被套)。 |
| `--upper` | 必填 | 區間上緣價。價格漲破它,所有賣單都已成交,手上全是現金(踏空)。 |
| `--grids` | 20 | 格數,區間切成幾格(共 格數+1 條價位線、同時掛 格數 張單)。 |
| `--invest` | 1000 | 本金,以計價幣計(如 USDT)。啟動時依「所有買單 + 初始持倉」預先分配,不會透支。 |
| `--mode` | `arithmetic` | `arithmetic` 等差:每格價差相同。`geometric` 等比:每格漲跌幅 % 相同。 |
| `--fee` | 0.001 | 單邊手續費率(0.001 = 0.1%)。一買一賣共付兩次。 |
| `--stop-loss` | 無 | 停損價,須低於 `--lower`。觸發後全數賣出並停止(連續行情以停損價出場,跳空時以當下價格出場)。 |

**怎麼選:**
- **區間:** 涵蓋你預期的震盪範圍,常見做法是現價 ±10~15%。太窄容易跑出區間,太寬則格距變大、成交變少。
- **格數:** 決定格距,約等於 區間寬度 ÷ 格數。**格距必須大於來回手續費的打平點** 2f/(1-f)(預設約 0.2%),建議至少 3~5 倍,否則每次套利扣完手續費所剩無幾,甚至虧損。格距不足時 CLI 會警告。
- **模式:** 區間窄時兩者差異很小。區間很寬(例如上下緣相差一倍以上)時,用等比較能讓每格獲利率一致。
- **停損:** 先決定最多願意虧多少,再倒推停損價。例如下緣再往下 5%。

### `backtest`:回測

| 參數 | 預設 | 說明 |
|---|---|---|
| `--symbol` | — | Binance 交易對,如 `BTCUSDT`。與 `--csv` 擇一。 |
| `--csv` | — | 自備資料,欄位 `ts,open,high,low,close`。第一列可為標題、空白行略過、毫秒時間戳自動轉秒;格式錯誤、NaN、價格不合理或時間倒退會報錯並指出列號。 |
| `--interval` | `1h` | K 線週期,如 `15m`、`1h`、`4h`、`1d`(搭配 `--symbol`)。 |
| `--limit` | 500 | K 線根數。超過 1000 會自動分頁往回抓;只取已收盤的 K 線。 |
| `--vol` | 0.01 | 僅合成資料用:每根 K 線的報酬標準差。 |
| `--seed` | 42 | 僅合成資料用:亂數種子,同種子結果相同。 |

`--symbol` 和 `--csv` 都沒給時,會以區間中點為起點產生**合成隨機漫步資料**,只適合測程式,不代表真實行情。

輸出包含:期末權益與損益、同期買入持有報酬、最大回撤、買賣次數、完成套利次數、網格利潤(估算)。

### `sweep`:參數掃描

| 參數 | 預設 | 說明 |
|---|---|---|
| `--symbol` / `--csv` | `BTCUSDT` | 資料來源,擇一;都沒給時預設 BTCUSDT。 |
| `--interval` | `1h` | K 線週期。 |
| `--limit` | 1000 | K 線根數(>1000 自動分頁)。 |
| `--grids-list` | `10,20,30,40,60` | 要測試的格數,逗號分隔。 |
| `--range-pcts` | `5,10,15,20,30` | 要測試的區間寬度,以起始價 ±% 表示(10 = ±10%)。 |
| `--modes` | `arithmetic,geometric` | 要測試的模式。 |
| `--split` | 0.7 | 樣本內比例:前 70% 用來排名,後 30% 當樣本外檢驗。1 表示不切。 |
| `--rank-by` | `in` | 排序依據。`in` 依樣本內;`out` 依樣本外(等於用樣本外挑參數,數字會偏樂觀)。 |
| `--stop-loss-pct` | 無 | 停損設在下緣再往下 N%。 |
| `--invest` / `--fee` | 1000 / 0.001 | 同網格參數。 |
| `--top` | 10 | 顯示前幾名。 |

**怎麼讀:** 看樣本內排名前幾的組合,在樣本外是否仍然賺錢。樣本內很好、樣本外很差,就是過擬合。格距吃不過手續費的組合會自動略過。

### `walkforward`:滾動視窗驗證

| 參數 | 預設 | 說明 |
|---|---|---|
| `--symbol` / `--csv` | `BTCUSDT` | 資料來源,擇一;都沒給時預設 BTCUSDT。 |
| `--interval` | `1h` | K 線週期。 |
| `--limit` | 3000 | K 線根數(>1000 自動分頁)。 |
| `--train` | 720 | 訓練段根數(1h K 線約 30 天)。每折在這段挑出最佳參數。 |
| `--test` | 240 | 測試段根數(約 10 天)。把挑出的參數套到這段從沒看過的資料。 |
| `--step` | = `--test` | 視窗每次前進幾根。預設等於測試段,測試段彼此不重疊。 |
| `--grids-list` | `10,20,30,40` | 候選格數。 |
| `--range-pcts` | `5,10,15,20,30` | 候選區間寬度(起始價 ±%)。 |
| `--modes` | `arithmetic,geometric` | 候選模式。 |
| `--stop-loss-pct` | 無 | 停損設在下緣再往下 N%。 |
| `--invest` / `--fee` | 1000 / 0.001 | 同網格參數。 |

**怎麼讀:** 最後幾行最重要。「訓練平均」和「測試平均」的差距代表過擬合程度;測試段平均接近 0 或為負,代表「用歷史挑參數」沒有預測力。「測試段串接複利」可與同期買入持有比較。

### `paper`:模擬盤

網格參數同上(`--lower`、`--upper` 必填),另有:

| 參數 | 預設 | 說明 |
|---|---|---|
| `--symbol` | 必填 | Binance 交易對,如 `BTCUSDT`。 |
| `--source` | `ws` | 價格來源。`ws`:WebSocket 逐筆成交價,斷線自動重連,連續失敗會改用輪詢,並每 60 秒再試回 WebSocket。`poll`:定時輪詢 REST 現價。 |
| `--interval` | 5 | 輪詢間隔秒數(`poll` 模式,以及 `ws` 退回輪詢時)。下限 0.5(避免被 Binance 限流),且須小於 `--stale-warn`。 |
| `--stale-warn` | 30 | 超過 N 秒沒收到任何行情資料(成交或 WebSocket 的 ping)就警告並響鈴,之後每 60 秒再提醒一次。`ws` 模式須大於 10。 |
| `--stale-halt` | 300 | 超過 N 秒沒收到任何行情資料就存檔並自動停機(退出碼 3)。0 表示只警告不停機。須大於 `--stale-warn`。 |
| `--alert-cmd` | 無 | 警報時在背景執行的 shell 指令(見下方「斷線警報」)。 |
| `--state` | `state/paper_<SYMBOL>.json` | 狀態檔路徑。同一個狀態檔同時只允許一個行程使用。 |
| `--reset` | 關 | 忽略既有狀態檔,重新開始。 |
| `--max-polls` | 0 | 處理幾筆成功取得的價格後結束(取價失敗不計)。0 表示持續執行。 |

**行為重點:**
- **自動接續:** 狀態定期存檔,重跑**完全相同的參數**就從上次接續;參數或交易對不同會拒絕,需加 `--reset` 或換 `--state`。
- **區間必須包住現價**,否則會報錯並建議區間(現價 ±10%)。
- **畫面:** 終端機中每秒原地更新一行(時間、現價、權益、套利次數、下一買 / 下一賣與距離);輸出導向檔案時改為約每 30 秒一行。
- **結束:** Ctrl+C 或 SIGTERM 會在處理完目前這一步後存檔結束(不會打斷狀態更新);再按一次 Ctrl+C 強制結束,此時不存檔,接續時以上一次存檔為準。

### 退出碼

| 碼 | 意義 |
|---|---|
| 0 | 正常結束(含 Ctrl+C / SIGTERM、停損清倉) |
| 2 | 參數錯誤、檔案或網路錯誤、狀態檔被其他行程使用 |
| 3 | `paper` 斷線過久自動停機(非停損,重跑同一指令可接續) |

## 斷線警報與自動停機(paper)
- 價格來源沒資料時每秒送心跳,主迴圈據此計算「已幾秒沒收到任何行情資料」。收到 Binance 的 ping 也算連線活著,所以冷門交易對長時間沒成交不會被誤判為斷線。WebSocket 連線若 30 秒完全沒資料會主動重連;連線各階段逾時 5 秒。
- 計時使用不受系統校時影響的 monotonic 時鐘。
- 警告每 60 秒重複一次;價格恢復時顯示中斷秒數。停機是存檔後以退出碼 3 結束,**不是**停損,不會賣出持倉。
- `--alert-cmd` 會在 warn / halt / recover 時在背景執行,訊息在環境變數 `GRIDBOT_ALERT_MSG`,等級在 `GRIDBOT_ALERT_LEVEL`。結束前最多等 5 秒讓指令送完。macOS 通知範例:
  ```bash
  --alert-cmd 'osascript -e "display notification \"$GRIDBOT_ALERT_MSG\" with title \"gridbot\""'
  ```
- 筆電休眠後喚醒,舊連線已死,可能直接觸發自動停機,重跑即可。

## 運作原理
1. 區間切成 N 格(N+1 條價位線),現價下方掛買單、上方掛賣單,現價所在處留一個空檔。任何時刻恰有 N 張單。
2. 買單在 level *i* 成交 → 在 *i+1* 掛賣單;賣單成交 → 在 *i-1* 掛買單,賺取格差。
3. 每格數量固定,啟動時依「所有買單 + 初始持倉」配置本金,不會透支;上方賣單所需的幣以啟動時的市價買入。
4. **穿價才成交:** 價格必須越過掛單價才算成交,剛好碰到不算。
5. **停損:** 連續行情以停損價出場;跳空時以當下價格出場。跳空指中間有沒看到的走勢:模擬盤停機後接續、輪詢模式的每一筆、WebSocket(重)連線後的第一筆,以及回測中 K 線開盤價與前一根收盤價不同時。
6. 回測的 K 線內部路徑為保守假設(陽線先低後高、陰線先高後低,兩種走法中成交較少的那種),不含滑價。

風險:價格跌出區間會被套在持倉中(可用 `--stop-loss` 限制);單邊上漲會賣完而錯過漲幅。
回測與模擬盤都沒有模擬滑價、委託簿深度、交易所最小下單量,實際表現通常會更差。

## 目錄結構
```
gridbot/
  engine.py    網格引擎(GridConfig / GridEngine)
  backtest.py  K 線回測與績效
  sweep.py     參數掃描、滾動視窗驗證
  state.py     模擬盤狀態存檔(原子寫入、檔案鎖)
  watchdog.py  斷線監看(警告 / 自動停機 / 恢復)
  ws.py        精簡 WebSocket 客戶端(僅標準庫)
  data.py      CSV、Binance 公開 API、合成資料
  cli.py       命令列入口(python3 -m gridbot)
tests/         單元測試
state/         模擬盤狀態檔與日誌(執行時產生,已 gitignore)
doc/           過程文件
```
